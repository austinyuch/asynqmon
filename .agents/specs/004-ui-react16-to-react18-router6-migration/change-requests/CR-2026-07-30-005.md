## Design

### Dependency and tooling contract

- Pin `packageManager: yarn@4.18.0` and `nodeLinker: node-modules`.
- Replace Yarn Classic `--frozen-lockfile`/`--ignore-engines` usage with Yarn Modern `--immutable`.
- Upgrade `react-window` to 2.3.0 and remove obsolete DefinitelyTyped declarations.
- Upgrade `react-syntax-highlighter` to 16.1.1 so its Prism chain requests `^1.30.0`; retain the existing light HLJS imports unless the published API requires a local adjustment.
- Preserve Node `>=24 <27` compatibility metadata while keeping Node 24 in hosted CI and the container build.

### Virtualized list adapter

- Replace `VariableSizeList`/`ListChildComponentProps` with `List`/`RowComponentProps`.
- Supply option elements through typed `rowProps`, compute responsive row height using the existing function, and retain padding/overscan.
- Remove the v1 imperative `resetAfterIndex` cache hook because v2 owns recalculation from `rowHeight` and `rowProps`.
- Keep the forwarded MUI wrapper ref and attach listbox attributes to the virtualized list root.

### Route splitting

- Replace eager view imports in `App.tsx` with `React.lazy`.
- Wrap only `<Routes>` in a single `Suspense` boundary so navigation shell/state remains mounted.
- Use a minimal accessible loading fallback based on installed MUI primitives.
- Do not introduce manual chunk names until measured output proves the native dynamic-import graph insufficient.

### Ponytail ladder

1. The work exists to remove reproduced maintenance/security warnings and reduce initial delivery cost.
2. No standard-library virtualization or package-manager replacement exists.
3. React lazy/Suspense and Vite dynamic imports are native platform/tooling features and are preferred.
4. Existing dependencies remain the owners of virtualization and highlighting; only applicable upgrades are used.
5. Route boundaries are one-line lazy imports; no registry or loader abstraction is added.
6. The v2 adapter is the minimum needed to preserve the MUI listbox contract.
